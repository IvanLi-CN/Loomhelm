# Production deployment template

This directory is a validation-safe template for one Loomhelm installation using stable Caddy, dual Server/Worker slots, shared PostgreSQL and retained Web assets. It is not a production command and does not contain credentials, real hostnames or real image digests.

Copy the files into an installation-owned directory, publish the immutable Web tree at `<LOOMHELM_WEB_ROOT>/candidates/<candidate_id>`, provide secrets through a protected env file, substitute immutable image digests and run `docker compose --env-file <protected-env> -f compose.yaml config`. Generate a deployment envelope from the immutable candidate with `scripts/build-deployment-envelope --candidate-manifest candidate-manifest.json --server-image <server-image@sha256:digest> --worker-image <worker-image@sha256:digest> --output deployment-envelope.json`; do not edit the candidate manifest after publication. Do not run `docker compose down -v`; PostgreSQL and artifact volumes are durable state.

The stable deployment controller is intentionally represented as a separately pinned service. Build its image with `--build-arg LOOMHELM_COMPONENT=deployment-controller` and publish it independently from the normal candidate. It is the only service allowed to access the host control boundary. Candidate promotion changes the inactive Server/Worker slot and Caddy route; it does not replace the controller.

The template keeps `/api`, `/mcp`, `/gateway`, health/version and drain routes visible through Caddy. Private Server/Worker `/-/observe` endpoints are not published by Caddy and are reachable only from the controller over the application/control network; they expose bounded counters and queue gauges for traffic and load observation without credentials or request-level labels. River queue depth is an installation-level shared metric, while running jobs and capacity are reported for the observed Worker generation. Caddy admin binds to the declared `caddy-admin` network IP and the `caddy-control` alias exists only on that private network; it has no host port. The controller joins both `caddy-admin` and the separate drain `control` network, while candidate Server/Worker services join the drain network but not the Caddy admin network. Caddy binds admin only on the admin-network interface, so application and drain peers cannot reach the admin listener. Both Worker services use the `deployment-controller` Compose profile, so an unqualified Compose start cannot admit a Worker generation; the controller explicitly targets one Worker service during promote or rollback. The controller invokes the fixed `/-/drain` endpoints over the private drain control network with an in-memory Authorization header, so the drain token never appears in Docker argv. The same `LOOMHELM_WEB_ROOT` host directory is mounted read-only at `/srv/web` and `/opt/loomhelm-web` for Caddy and controller digest verification, while installation files use a separate `/opt/loomhelm-install` mount. Choose non-overlapping control and Caddy admin subnets for the installation and replace the example Traefik labels with the installation's existing labels without exposing the admin endpoint.
