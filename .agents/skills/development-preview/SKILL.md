# 开发预览

本 Skill 服务于本仓库开发。完成存在可交互页面的 UI 改动后，默认主动构建并在 Codex 内置浏览器打开相关预览，保留服务与标签页供主人检查；主人明确要求预览时也使用本流程。纯文档、后端和无界面改动不自动启动预览。正式编排与已安装工具的使用遵循各自使用 Skill。

## 选择与启动

1. 读取[模块预览说明](../../../docs/development-preview.md)，确认当前工作树、源码改动、预览入口与能展示目标行为的示例。开发预览从当前工作树构建；记录 HEAD 与未提交改动，不能仅用 HEAD 声称页面身份。
2. 启动前读取 `$global-port-manager`，核对当前宿主实际提供的后台能力。需要跨回复保留的预览必须取得真实的 Codex native background session，并保留宿主返回的标识与运行状态证据。普通 exec/PTY 返回的 session ID、存活 PID 和端口租约各自只证明对应事实，不能据此推断原生后台托管成立；不创建或猜测宿主会话标识。
3. 使用模块已有源码服务及其端口租约机制。已有入口自行申请租约时复用该流程；其他入口先分配并注册当前任务的端口。使用隔离演示数据，保持正式服务与真实账本的身份独立。
4. 检查构建结果、服务进程、active lease 与 HTTP 响应，再核对当前宿主暴露的内置浏览器能力，按工具文档在内置浏览器打开对应场景。此开发预览交付路由优先于通用 `$ego-browser` 偏好；只有宿主无可用内置浏览器时才走允许的 `$ego-browser` 路由，打开或登录失败先诊断，不自动切换浏览器。遵循 `$gui-escalation-gate` 的浏览器升级约束。

宿主没有支持的后台路径时，完成不依赖它的构建和内部验证，明确报告预览交付的宿主阻塞及缺少的能力。内部验证期间的 live exec 可访问性不构成跨回复交付；不以可见终端、脱离监管的进程或已安装正式服务替代开发预览托管，也不为绕过阻塞自行安装常驻服务。

## 验证与交付

- 在页面实际检查本次目标行为；需要悬停、点击或展开的改动必须进入相应状态。确认页面来自本次成功构建，构建失败仍服务旧资源时明确说明，修复后重新验证。
- 交付前分别核对页面可访问与跨回复服务托管，后者使用宿主提供的真实状态证据；不将“端口正在监听”表述为“后台会话有效”。
- 向主人报告预览来源、示例场景、已检查的行为、刷新或重启方式及生命周期。只有托管与端口所有权均已核实才交付 localhost 链接；单次登录票据只通过浏览器导航消费，不写入普通回复或文档。
- 保留预览标签页与符合要求的服务，主人确认结束或清理后只关闭本任务精确拥有的资源。服务失效时报告失效并按相同所有权合同恢复，不能继续声称可访问。

预览交付和截图验收分别执行。UI 视觉证据继续使用 `$ui-visual-evidence`；真实程序截图逐次取得目标程序与范围授权，本 Skill 不扩大截图授权。
