# Development

Run `scripts/setup` from the repository root to verify the required Git, Go `1.27.2`, Bun `1.4.3`, Python 3.9+, and sqlc `1.31.1` toolchain, prepare the pinned Markdown tools, copy `.env.example` only when `.env.local` is missing, and install frontend dependencies. `SQLC_BIN=/path/to/sqlc scripts/setup` supports a repo-local or user-selected verified binary without changing global PATH; the official URL and SHA256 come from `tools/database-toolchain.json`. Docker and Compose are optional setup dependencies for the PostgreSQL workflow, while `scripts/dev` requires them when used; Goose and River are Go module dependencies rather than standalone setup binaries.

Setup aggregates missing tools, version mismatches, manifest errors, environment-file conflicts, Markdown setup failures, and Bun install failures before exiting nonzero with a recovery hint. A regular `.env.local` or a valid symlink to a regular file is preserved; directories and dangling symlinks are rejected without following or overwriting external targets. Setup never installs hooks or changes global PATH, proxy, or authentication settings; install Lefthook explicitly when the local workflow calls for it.

The local PostgreSQL service is defined in `deploy/dev/compose.yaml`. Run `scripts/dev up -d` to start it, `scripts/dev ps` to inspect health, `scripts/dev logs -f postgres` to follow logs, and `scripts/dev down` to stop the service while retaining its named volume. By default `scripts/dev` derives a stable Compose project name from the canonical Git worktree path, so linked worktrees receive separate networks and volumes; set `LOOMHELM_DEV_PROJECT_NAME` only when an explicit resource owner is intended.

The example database URL points at `127.0.0.1:55432` and is intended only for local development. Keep `LOOMHELM_POSTGRES_PORT` synchronized with the port in `LOOMHELM_DATABASE_URL` in each worktree's `.env.local`; export both values from that same file before starting Server or Worker or running a database command (for a POSIX shell, `set -a; . .env.local; set +a`). `LOOMHELM_STARTUP_TIMEOUT` defaults to `10m` so the online artifact index migration can finish on a large table; `LOOMHELM_DATABASE_MIN_CONNS=0` delegates the minimum to pgx, and `LOOMHELM_DATABASE_MAX_CONNS=4` caps the pool by default. `scripts/dev` passes the selected file to Compose and never kills or adopts an unrelated listener.

After exporting the paired development variables, run `scripts/db migrate` to apply the embedded Goose application migrations and the River queue migrations under one PostgreSQL session advisory lock. The command uses the same database-only environment parser as Server and Worker, including the development-target and pool-size checks, before opening a connection. The application schema lives in `db/migrations`; River owns its queue tables separately and is migrated by the same command.

Approval revision history rollout is explicit and pauseable: run `go run ./internal/platform/database/cmd/migrate --operation prepare`, then repeat bounded `backfill`, `validate`, `indexes` and `cutover` operations as needed with `--batch-size`, `--work-budget`, `--lock-timeout`, `--statement-timeout`, `--lease-duration` and `--timeout`; use `--operation status` to inspect durable phase and progress. `indexes` runs outside the startup migration lock, and normal application startup remains fail-closed until `cutover_complete` with no dirty rows. A database carrying the previous atomic 00012 layout must use the explicit `--operation adopt` path; it is never inferred or replayed by the default migration command.

After exporting the paired development variables, run `scripts/db test` for the database/job, authentication, project/task and Server composition tests. Database-backed tests validate the shared development target and pool settings before opening a connection, then skip only when `LOOMHELM_DATABASE_URL` is unset; configuration and serialization tests remain runnable without services. The Server composition exercise creates and drops its own randomly named schema, runs a disposable signed-token OIDC issuer, and verifies real HTTP login, cookie sessions, same-origin protection, CRUD, permissions and session/data persistence after Server restart. Its database user needs schema-creation permission; the test never changes a real identity provider or copies a user's login state.

Server mounts application routes under `/api/v1`; the deployment proxy must serve the Web app and this namespace from the same origin. Set `LOOMHELM_OIDC_ISSUER_URL`, `LOOMHELM_OIDC_CLIENT_ID` and `LOOMHELM_OIDC_REDIRECT_URL` together to enable OIDC; the redirect must be the public application's absolute HTTP(S) URL ending in `/api/v1/auth/oidc/callback`. Supply `LOOMHELM_OIDC_CLIENT_SECRET` only when required by the issuer. Browser login starts at `/api/v1/auth/oidc/start`, and discovery failure prevents Server startup. Leaving OIDC unconfigured keeps login unavailable with HTTP 503 and does not grant anonymous access to application data. Worker and Connector ignore these settings.

`LOOMHELM_SESSION_COOKIE_SECURE` defaults to `true`. Keep that value behind an HTTPS proxy; use `false` only for an explicitly isolated plain-HTTP development endpoint. Session cookies are HttpOnly and SameSite=Lax. `GET /api/v1/auth/session` returns the authenticated browser identity and `csrf_protection: same_origin` with `Cache-Control: no-store`; a bearer token cannot stand in for a browser session. `POST /api/v1/auth/logout` destroys the current browser session without revoking separate API credentials. Application requests pass the standard-library `net/http.CrossOriginProtection` middleware with no trusted-origin or bypass exceptions; API/MCP clients still need their own credentials and project authorization. New application requests receive HTTP 503 during drain, while already admitted requests retain the HTTP shutdown lifecycle.

The checked-in sqlc configuration is `sqlc.yaml`. Run the same verified absolute sqlc `1.31.1` binary used by setup again, for example `/absolute/path/to/sqlc generate`, or export it and run `"$SQLC_BIN" generate`; a one-command assignment such as `SQLC_BIN=/absolute/path/to/sqlc scripts/setup` applies only to setup and does not put the binary on PATH for a later bare `sqlc generate`. The F03 database entry reads schema from `db/migrations`, reads queries from `internal/platform/database/queries`, and writes Go code to `internal/platform/database/generated` with `sql_package: pgx/v5`.

Each generated storage package includes only table and enum structs used by its own queries, using sqlc's [`omit_unused_structs`](https://docs.sqlc.dev/en/latest/reference/config.html) option. The full migration schema is still parsed and validated. Adding another domain's tables therefore does not export those domain models from the platform package; query or relevant schema changes still require regeneration and a clean `scripts/checks generated` result. Domain query packages retain separate output ownership when added to the shared configuration.

The public REST/MCP and command/event contract is `contracts/loomhelm-v1.json`. Run `scripts/codegen` to regenerate the Go protocol package, TypeScript protocol package and typed REST client; run `scripts/codegen -check` to fail when any generated file differs from the canonical contract. `go generate ./internal/protocol` uses the same generator and contract path.

The backend image is built with `docker build -f build/Dockerfile --build-arg LOOMHELM_COMPONENT=server .`. The image is a build surface for the separate Server, Worker and Connector processes; process composition remains in the application entrypoints.

The immutable candidate build and promotion contract is documented in [Candidate Builds](candidates.md). Use `scripts/build-candidate --source-sha <full-sha>` to build the Server, Worker, Connector and Web static assets from one clean source SHA, and use `scripts/promote-candidate` to verify and promote an existing artifact by its recorded digest without rebuilding. The isolated branch preview uses `scripts/preview init`, `scripts/preview stage path/to/candidate-manifest.json`, `scripts/preview check`, `scripts/preview promote` and `scripts/preview rollback`. It requires an exported PostgreSQL URL, drain token, unique `LOOMHELM_PREVIEW_PROJECT_NAME`, and four ports registered for the current worktree through `$global-port-manager`; the Compose file has no shared project or fixed port defaults. It keeps deployment state outside Git by default in `.loomhelm-preview/` and uses the session-owned Agent VM for Docker/Compose rehearsal. Staging admits a Worker only after Server, Web digest, image reference and candidate identity checks; a failed candidate is cleaned up and the active Worker generation is restored. Promotion validates both Server and Worker readiness, reloads Caddy, records the exact candidate identity, retains multiple compatible Web generations and drains the retiring slot; it is not a production deployment command.

Markdown checks use `python3 tools/markdown.py check`; the Lefthook configuration runs the staged Markdown formatter without auto-installing hooks or tools. The same hook runs the pinned React Doctor check for staged `web/src` TypeScript/JavaScript files; no changed React files produces an explicit skip, Doctor errors fail the hook, and warnings remain visible without blocking it.

The unified repository checks are exposed by `scripts/checks`. `scripts/checks quality` validates the checked-in quality-gate declaration, pinned dprint Markdown output, shell/Python syntax and both development/branch-preview Compose configurations. `scripts/checks generated` validates public contract output, sqlc output and module drift; `scripts/checks source` runs Go tests, race tests, shuffled tests and vet; `scripts/checks database` requires `LOOMHELM_DATABASE_URL` and runs the real PostgreSQL-backed database and River job tests; `scripts/checks web` runs frozen Bun installation, typecheck, Vite/PWA and Storybook builds. Each failed command reaches the group result, and `scripts/checks all` returns nonzero when any group fails.

React Doctor is pinned by `REACT_DOCTOR_VERSION` in `tools/versions.env` and the root Bun lockfile. CI computes the changed React file range from the checked-out base ref; a Git range calculation failure blocks the `React Doctor` check, while an empty range is a successful explicit skip. Doctor uses `--blocking error`, so error findings fail the check and warning findings remain visible without changing the result.

The canonical bootstrap entrypoint is `scripts/setup`; it does not depend on historical setup helpers, so a linked worktree from an older revision can recover by running the current repository entrypoint after the files are present. The bootstrap contract is copy-missing and repeatable: it preserves existing environment files and hooks, supports linked worktrees whose `.git` is a gitdir file, and never writes to the shared Git common directory unless an explicit hook installation command is run.
