# ADR 0021：Bun 直接运行客户端与 Skills

## 状态

accepted。取代 ADR 0017 的 Node/Bun 双运行时决定及 ADR 0019 的自建 Node-API 适配决定；它们的历史背景保留。

## 背景

Skills 通过源码目录安装，而官方入口与客户端执行器要求预生成 JavaScript，造成源资源完整但命令不能启动。跨运行时适配又引入平台原生构建，增加安装前提。主人已决定客户端和迁入 Skills 仅支持 Bun。

## 决策

生产统一使用仓库固定的 Bun 1.4.4 直接执行 TypeScript。CLI、SDK、Skills 和本机 viewer 的源入口保持一致；资源包复制源码与完整依赖，类型检查不生成生产 JavaScript。浏览器资源仍按其前端构建合同生成。

删除自建 Node-API 模块及其头文件和编译链。通过 Bun 内置 FFI 调用系统库，保留目录描述符操作、文件身份和权限检查、flock 与原子不覆盖重命名。复用已迁入固定源版本的行为，不重写业务或另建锁协议。

Dev Plan 通过受验证入口描述符读取 TS，再从私有、经检查的 TS 快照加载校验器。不得以直接重新打开活动源码或跳过预加载隔离替代原有信任边界。

本机服务新包采用 v2 清单，携带 TS、依赖与浏览器资源。旧包可识别和诊断，但不得作为新源码入口的隐式回退。用户已安装服务和真实账本不自动迁移。

## 取舍

取消 Node 运行兼容、旧 dist 导入路径及自建二进制供应成本，代价是用户必须具备固定 Bun。旧运行的 schema、身份、revision、锁路径与 flock 协议保留。平台能力只声明已验证的 macOS arm64 和 Linux x64 glibc。

这项决定不授权修改用户级安装、其他项目、分支规则或部署服务。

viewer 的最小启动胶水只使用 Bun 内置模块验证资源，不编译或打包服务端 TS。受信任启动器绑定资源清单身份，先验证全部文件再加载 TS；包内配置不参与启动前的运行时配置加载。私有临时目录与祖先遵循可信 owner、权限及 sticky-root 规则。

导入前完整性检查必须枚举整个包，拒绝未列文件，不能只验证清单中的文件。包内目录和文件不适用 sticky-root 权限例外，避免模块解析绕过已验证资源集合。

从密封 finalizer 改为源模块快照后，信任检查覆盖完整执行闭包而不只入口：源文件和目录必须属于 root 或当前用户，且不可被 group/other 写入；描述符读取前后保持相同检查。

自有客户端与 Skills 源代码统一为 TS，包括维护脚本及测试；构建只复制源文件和声明资源。浏览器端编译与第三方依赖的文件格式独立保留。
