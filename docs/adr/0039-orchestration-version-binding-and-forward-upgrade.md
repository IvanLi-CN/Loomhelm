# ADR 0039：编排版本绑定与前向升级

## Status

Accepted。主人已确认本记录的需求与范围；程序实现与隔离验证按本记录推进，发布和正式运行升级尚未执行。

## Context

[ADR 0038](0038-interrupted-initialization-recovery.md) 与已合并的 PR #310 已实现中断初始化的单次原生握手恢复、持久 attempt、原生 writer 排斥、恢复链核验和创建预算扩展。该能力保持既有 ledger contract，不要求迁移历史数据，不能将其再次规划为本任务的新实现，也不能声称初始化恢复必然要求新合同版本。

本主题处理另一条边界：调用的 CLI、编排绑定的运行版本、账本数据合同和对应 Worker 必须一致。安装或运行新 CLI，不等于某个既有编排已经升级。仅证明旧 reader 保留新增字段，不能证明旧 writer 执行了新版本的全部约束。

现有存储分成两部分：`runs/<run-id>/ledger.json` 保存计划、任务、依赖、操作、事件和数据合同；`runs/<run-id>/runtime/viewer-binding.json` 保存包版本、build、source SHA 和运行合同绑定。当前绑定实现主要服务 Viewer/Worker 选择，普通 flow 入口没有完整的 CLI 身份匹配门禁。现有 orchestration upgrade 只接受相同合同的切换，没有自动完成跨合同账本迁移。

## 已确认的需求

- 普通 flow 命令（包括只读命令）严格匹配编排绑定版本，不匹配则拒绝。专用只读兼容检查和 upgrade dry-run 可以读取历史信息，但不产生业务写入、绑定切换或隐式升级；升级入口不能被普通命令门禁自身锁死。
- 升级由 CLI 自动完成目标版本所需的数据迁移和绑定切换，不要求主人手工改账本，也不能只更新绑定却留下旧数据合同。只有显式调用 orchestration upgrade 才触发升级；普通命令版本不匹配时拒绝并给出升级命令，不静默迁移。
- 编排升级在 CLI 侧不可逆，不提供降级或反向数据迁移。备份用于独立灾难恢复，不能伪装成普通 CLI rollback；失败应前向修复。
- 升级需要同时覆盖账本和版本绑定两个持久对象；升级中断时不能放行不一致状态的普通写入。锁、恢复记录和完成判据需要共同约束 CLI 与 Worker，daemon 通知不能承担正确性职责。
- 迁移只允许可验证的机械转换，不推断或改写业务语义、owner、已有对话、工作区或外部事实；缺少目标身份或迁移证据必须阻断。
- 升级中断后只允许显式 upgrade 续跑已登记的同一次升级；持久化源身份、已解析的不可变目标身份和进度。普通命令继续拒绝，标签重试不重新解析，不自动回滚或切换目标。
- 安全升级点冻结该编排的新写入，等待正在执行的 CLI/Worker 写事务及原生副作用调用安全退出；只读连接不无限阻塞升级。静止的 unknown operation、claim 和容量原样迁移，不要求任务全部完成；无法证明副作用已停止时阻断，不强杀后假称安全。
- 普通命令匹配完整的包版本、build ID、source SHA 和合同集合；同版本号不同构建也拒绝。缺失身份只能进入专用诊断和显式升级处理，不根据 latest 或当前全局安装猜测。

## 与既有合同的关系

本记录替代 [ADR 0034](0034-stable-gateway-versioned-workers.md) 中的编排 `--rollback` 与向旧运行身份切换规则，并补充 [ADR 0028](0028-multi-task-flow-version-propagation-and-safe-migration.md) 的版本传播和迁移边界。Gateway 更新及其回滚仍是独立主题，不因禁止编排降级而自动取消。

初始化恢复继续遵循 ADR 0038。共享绝对 deadline、外层结构化超时诊断属于待评估的剩余差异，不能用本地未合并的 60 秒收尾预算覆盖 #310 已合并的 200 秒余量，也不能将它们写成当前已发布行为。

## 历史来源与执行边界

历史编排缺失可信绑定时，普通命令拒绝，专用诊断及 upgrade dry-run 报告缺失项。只有来自该编排的可验证历史证据能唯一确定源身份时，显式升级入口才可机械补齐。证据不足时暂停并请求可验证的来源，不按当前 Gateway、全局安装或 latest 猜测。

升级由目标版本的 CLI 执行，目标不可变身份必须与该 CLI 的已验证 artifact 一致。升级入口对源绑定版本不匹配作有限例外，普通命令没有该例外；旧 CLI 不负责解释未来版本迁移。

后续实现只聚焦编排版本绑定及前向升级，复用 ADR 0038 的初始化恢复和 200 秒余量。共享绝对 deadline、外层结构化超时增强保留为独立后续候选，不将当前未合并实现混入升级主题。

## 验收方向

验证普通 CLI 命令（含只读）版本不匹配时拒绝且不隐式升级，专用诊断及 dry-run 无业务副作用；升级前后的包/build/source 与数据合同匹配；历史来源读取和迁移幂等；账本迁移与绑定切换之间各崩溃点的安全识别；旧 CLI/Worker 无法写升级后数据；降级被拒绝；失败可前向续跑；Gateway 版本和其他编排绑定不受影响。可执行需求与验收见主题 Spec 的编排版本绑定与前向升级章节。

程序实现及隔离验证在当前工作区推进；完成前不视作可发布候选。正式 LIMS、daemon、全局安装、账本与版本绑定均不在本轮变更范围内。

## 原子发布屏障

主人已确认使用整个 run 目录的原子发布：在既有维护、账本和绑定锁内构造私有候选目录，原子交换 run 与候选目录，同时发布 contract-4 账本、prepared 升级记录及 schema-2 绑定。源目录保留为隐藏恢复快照，名称写入升级记录；它不是另一个正式编排，也不作为自动回滚入口。源账本和源绑定的摘要必须与恢复快照一致。发布前中断没有已接受的升级事务，原 run 保持原格式；发布后只允许续跑已登记的目标。

采用此屏障的原因是旧版 orchestration-upgrade 可以只读写 viewer-binding 而不读取 ledger。只提升 ledger contract 无法阻止该入口改写绑定。原子目录发布使旧 flow 遇到不支持的 contract、旧维护入口遇到不支持的 binding schema；不会出现其中一个已迁移而另一个仍可被旧入口写入的持久窗口。绑定正常更新只允许显式前向事务，新版低层写绑定函数也拒绝直接修改 schema 2。

发布依赖平台和文件系统提供的原子目录交换能力，不以多次普通 rename 模拟。源目录、候选目录及共同父目录必须通过身份与无符号链接校验；不支持原子交换时阻断。持有旧目录锁的读者在取得锁后必须重新验证目录身份；等待生命周期锁的新版调用在执行任何动作前重新获取当前目录的锁。恢复快照和发布前残留的候选目录不自动清理。
