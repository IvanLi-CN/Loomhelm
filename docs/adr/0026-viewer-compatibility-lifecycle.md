# ADR 0026：Viewer 兼容生命周期与历史状态处置

## 状态

Accepted，2026-11-10。

## Context

Viewer 发布同时改变读取代码、写入格式和本地网页呈现；历史 run 可能长期保留，并且升级、回退和只读展示有不同的兼容要求。

2.0.1 将 `child_review` 替换为 `task_quality`，但旧 run 仍包含前者，导致候选 viewer 无法读取历史账本。仅在 manifest 中声明旧合同可读不足以证明兼容，完整账本读取必须通过实际 reader 验证。

## Decision

Viewer 兼容按以下优先级处理：最新 viewer 首先提供对当前格式和仍受支持历史格式的双读；只有最新 viewer 无法安全解释某个历史格式时，才允许使用旧 viewer 作为隔离的只读视图；两者都无法证明读取安全时，升级必须阻塞。

旧 viewer 只读兜底不得写入新账本、改变 owner、推进 revision 或执行业务 mutation。它只能在明确的历史视图边界内读取原始状态，并保留原 run 身份。

自动迁移只适用于机械、无语义推断、幂等、可恢复且可验证的转换。迁移必须先生成并校验完整备份，使用 revision、内容 digest 和唯一 request identity 防止并发覆盖，迁移后验证新 reader 可读；无法从旧事实推导新事实的转换必须保留旧数据或进入明确批准的人工处置。

历史内容默认不自动清理。归档、标记过时、从 active projection 移出或删除原始证据都必须是独立的、逐 run 的维护动作，并保留审计和恢复材料。

兼容代码清理是独立的 release-level 决策，不要求与数据迁移同时发生。只有在维护者确认支持范围内不再需要旧 reader、旧 viewer 不再是允许的 rollback 目标，并更新维护文档后，才可删除生产兼容分支。历史格式测试、迁移测试、旧 viewer 只读测试和拒绝路径测试必须保留。

## Consequences

升级路径会保留一个可验证的 bridge release，避免把历史状态处置强行塞进代码切换。代价是 reader 在兼容窗口内需要维护多个格式，且旧 viewer 只读兜底需要明确的隔离边界。

自动迁移的适用范围较窄，但不会把缺失的历史证据伪造成新事实。过时内容不会因为升级而静默消失；维护者可以在独立时间点基于审计证据处置它们。

## Verification

每个 viewer candidate 必须在切换前对全部保留 run 执行实际读取预检，并记录 source/target build、合同、revision、原始 digest、读取能力和错误。兼容测试必须覆盖双读、旧 viewer 只读隔离、机械迁移幂等性、迁移中断恢复、回退边界和不可证明转换的阻塞行为。
