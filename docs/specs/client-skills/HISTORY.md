# 客户端 Skills 兼容历史

本主题承接原客户端设计中 Skills 与脚本迁移的完整范围。此前仅参考源语义实现本地阶段 API 和独立任务图，未交付实际源包，不能作为完整迁移基线。

主人确认 Multi-task Flow 的 proposal 必须与实施授权严格分离，并补充计划完整性、结构化验收合同、交付单元收口路径、依赖语义、regular 协调者就绪和 dashboard 不可调度标识的长期设计约定。该决定先形成 SPEC 与 ADR；当前账本、validator 和 viewer 尚未因此自动升级。

主人确认迁入 dot-codex 自有的 29 套源包，排除 `~/.agents` 的外部源包，保留本地编排网页，并直接兼容现有 schema2/contract2 运行。旧运行的读取、合法写入与所有权是独立边界，不以强制导入代替兼容。

共享支持曾位于根 `bin/`，导致 vendor 仅检出 `skills/` 后缺失运行模块。安装边界收敛为 `skills/` 单目录；支持代码、合同归档、构建与依赖声明全部归入该目录，不通过扩大用户级 sparse checkout 规避迁移缺陷。历史运行格式、真实账本与用户服务不变。

编排网页由 Cytoscape/Dagre 切换为 React Flow/ELK，以正交路由与可读 HTML 卡片改善复杂依赖追踪。保留账本 schema2/contract2、任务投影、原生对话链接和服务鉴权合同；单交付单元任务视图改为默认网格，显式 URL 布局仍优先。独立 example 以全新合成领域、标识、时间与回执复现多分支汇聚及发布链，不提交真实运行账本。

运行合同改为 Bun 1.4.4 直接执行 TS，取代原 Node/Bun 双运行时及 Node-API 适配。移除预编译 JS 与 C 构建要求；持久化格式、锁路径、owner、revision 及恢复语义不变，旧状态和现有用户服务不自动改写。

正式审查发现并修复 Bun FFI 缓冲区保活、旧 viewer rollback 启动边界和模块检查接线遗漏；既有账本及用户服务保持原处。

viewer 启动器先验证临时目录及祖先，再使用私有受控 Bun 配置；在任何包内 TS 或配置执行前，以启动器绑定的资源身份验证完整清单。FFI 路径拒绝嵌入 NUL，保持目录描述符边界。

viewer 的导入前检查同时拒绝清单外文件与包内可写权限异常，防止扩展名省略解析加载未验证模块；sticky-root 例外仅用于包外可信祖先。

Dev Plan 私有快照对每个源目录和文件检查 root/当前用户所有权及无 group/other 写权限，并对已打开描述符再次核验；嵌套模块不能绕过入口信任边界。所有 FFI 路径转换均拒绝 NUL，包括报告克隆路径。

客户端与 Skills 的自有维护脚本、生成工具和测试源文件统一为 TypeScript，由 Bun 直接运行；不因 Bun 可以执行 MJS 而保留自有 JS 入口。浏览器构建产物与第三方依赖中的 JavaScript 不属于该源码转换范围。

自有 TS 子进程及安装探测显式关闭 Bun 自动安装；依赖须先按声明准备，缺失时报告阻塞。安装报告独立列出本地依赖准备状态，不以祖先 checkout 的偶然依赖充当独立安装成功。

源码预览通过隔离 profile 的正式 daemon 生命周期运行，预览元数据不作为已安装发布包加载；生产启动仍要求 v2 源码包。回归直接启动默认、空闲归档和单交付单元三个预览命令，并验证鉴权、关闭及生产配置拒绝边界。

- Viewer 撤销 PATH 重写、运行时变量清理和强制 Bun 配置隔离；launchd 保存维护调用者 PATH，补充发布入口到 gh 子进程的环境传递回归。
