# 统一手动版本发布合同历史

## 合同来源

Owner 明确要求完全采用 Manual version release delivery，并确认服务端、Go 客户端、TypeScript 客户端与 Web/PWA 共享版本、源码身份及共同完成判定；无代码变更的组件也参与统一交付。

Owner 明确要求正确识别 TypeScript 客户端与 Go 客户端；Connector 不作为独立产品端。统一发版应收敛 Go 客户端现有独立发布链，保留两种客户端。先前将此解释为废弃 Go 实现或向 TS 迁移能力是文档编写错误，已纠正，不构成 owner 授权。

## 兼容性边界

保留既有历史 tag，不将 Connector 历史版本自动转换为产品 baseline。无可信 baseline 时首次统一发布必须由 owner 提供完整版本；合同制定时未选择首发版本，后续 owner 明确指定并授权 0.1.0。

允许已安装客户端与缓存 Web 暂留旧版本，真实报告版本并按兼容性规则连接；发布完成和全部终端已升级是不同事实。

## 项目适配确认

Owner 确认服务端、Go 客户端与 TypeScript 客户端 Linux amd64 为首批必需目标；正式产物长期保留，未完成身份的冻结产物保留至恢复或显式终止；使用独立 GitHub Issue 流程记录发版故障。本次不执行真实通知。

## 跨版本连接确认

Owner 确认首批保证同版本组合；旧客户端与缓存页面仅在明确声明并验证兼容后才能连接新服务端，否则提示受控升级。TypeScript 客户端独立本地能力继续可用。此规则覆盖两种客户端的联网能力及 Web/PWA。

## 实现边界

统一发版实现采用签名追加 Git ledger 与 draft Release 原件存储；发布准备仍走正常 PR。产品发布记录格式初始为 schema 1，只新增发布侧状态；没有业务数据库、Go journal 或 TS 本地账本的数据迁移。未知 ledger schema 必须拒绝读取，不自动转换或回退。

旧 Go 独立发版和候选独立公开入口改为提示进入统一入口；历史产物和 tag 保留，不重写、不当作统一产品 baseline。后续程序必须识别既有发布状态并向前修复，不能通过回滚程序撤销已公开资产或 reservation。

## 与 Bun 源码运行合同对齐

Owner 确认沿用主干 PR #76 与 ADR 0021 的 Bun-only 决定，将 TypeScript 成品安装验收从 Node 22／24 改为 Bun 1.4.4 直接执行源码及包内 FFI 行为验证。双平台、完整依赖与 Skills 资源、统一版本和原身份恢复要求保留；旧 Node 名称 required checks 仅沿用主干的兼容标识，不证明 Node 支持。

## 现有认证与保护核验修正

PR #77 合并后，owner 要求删除额外认证、签名私钥及无需求依据的强制 Rulesets 前置条件。后续实现保留统一发布合同，复用现有 gh / Actions 身份与平台签名 CAS，识别 main 原生分支保护，保留 owner 创建版本准备 PR 的现有权限边界。ADR 0023 接续该适配，真实首发与原身份恢复仍需完整版本输入和授权后实测。

## 按主干绑定与原发版意图区分版本复用

Owner 明确否定 main 前进就作废预留版本的处理：版本未落 main 时根据实际改动是否超过原意图判断能否继续使用；已落 main 的版本只能发布对应代码。ADR 0024 将准备阶段改为原 identity 内的签名追加修订，保留初始意图、既有版本与全部历史；构建、公开及已绑定后的不可变身份要求保持不变。

## 真实首发与独立修复

PR #92 实现意图核验后，原 0.1.0 reservation 经签名追加修订继续使用；PR #86 将该版本固定到 f2d268f462f7dd91d5b7bbeda45873c18d82b7f6。Release run 42450011670 完成完整八项资产、公开及 completion；完成后同身份只读恢复下载复核全部原件，未改 ledger、版本、SHA 或 digest。已落主干的 0.1.0 不因后续修复而重建。

按 owner 的先合并、低优先问题独立 follow-up 授权，修复非 main 合并误阻断、assessment 类型错误和实际发生的空身份附件通知失败，保留原主干绑定、来源校验、Issue 对账和 fail-closed 边界。未执行的真实故障注入仍保留为验收缺口。
