# 客户端 Skills 迁入与错误实现修复

## 交付目标

本次工作不是继续扩展一套参考原 Skills 语义的简化实现，而是将指定 Skills 及其对应脚本完整迁入本仓库，并消除此前以局部功能替代完整迁移的错误实现和完成声明。本文记录已确认需求和未决边界；主人已确认自有 29 套全部迁入、排除 ~/.agents 源包；外部宿主能力明确检测。实现与验收尚未完成时不得宣称迁移完成。

TypeScript 客户端继续独立位于 `clients/typescript/`，仅使用固定 Bun 1.4.4 直接执行 TS，不替换 Go 客户端。客户端同时承载服务端与 Codex 交互的集成能力，以及可以脱离服务端运行的开发任务辅助能力。本次 Skills 修复不等于 Connected mode 已实现。服务端、客户端、Web App 的名称和现有产品边界保持既定合同。

Skill 源包放在项目根目录的 `skills/` 下，每套有独立目录。以下 29 套是本次唯一指定的 Skill 清单；~/.agents 中的外部 Skill 不因引用关系自动纳入。

| `project-engineering-workflow` | 共享工程交付合同、阶段门禁与对应执行支持 |

| `fast-flow` | 快速交付路径及其授权边界 |

完整迁入包含实际 `SKILL.md`、适用的 references、模板、脚本、网页资源、测试，以及包外必要共享执行支持的来源和处置。不能只复制九个入口文件，也不能用名称相同但语义缩水的 TS 模块代替原包。运行时兼容改动须保留原有授权、幂等、对账、恢复和门禁语义；外部依赖按宿主能力合同检测，不复制其 Skill 源包。

## 已确认的行为边界

- 保留 Multi-task Flow 本地编排网页，包括任务图、进度、会话链接和实时更新；它属于客户端的本地界面，不改变 Web App 的产品边界。
- 直接兼容并接续既有 Multi-task Flow 运行，不能要求先导入或转换成另一套账本才能使用。需要分别验证读取、合法写入、继续执行、锁与所有权、未知结果对账和网页展示，不能把读取成功当作接续成功。
- 不修改 dot-codex、全局 Skills 或其他项目的程序，也不借本次修复操作其他任务和旧运行账本。兼容验证应使用可恢复的测试副本；真实运行的写入或所有权变更须另有明确授权。
- 依赖按必经硬依赖、场景硬依赖、可选增强和文档引用分类；外部能力缺失时明确适用阻塞，不自动安装或跳过门禁。

## 现有实现与原需求的偏差

| 原需求 | 已核实的现状 | 修复要求 |
| - | - | - |
| 迁入 Skill 源包与配套脚本 | 根目录没有 `skills/`；`.agents/skills/` 是既有工程 Policy，不能算作指定 29 套迁移成果 | 建立29 套实际源包及支持资源的可追溯清单 |
| 保留完整工程交付语义 | `clients/typescript/src/workflow/README.md` 明确仅参考本地阶段，`can-open-pr` 不代表完整审查、CI 或交付完成 | 对照源合同修复；本地阶段模块不得继续代称完整迁入的工作流 |
| 迁入 Fresh Thread Dispatch | 当前 `ThreadDispatcher` 提供注入式 app-server 适配与独立 `dispatch.json`，不能单凭此证明源 Skill 的宿主派发与交接合同已迁入 | 对照源包逐项核验宿主能力、授权、身份和交接；复用符合合同的底层能力 |
| 迁入完整 Multi-task Flow | 当前任务协调模块使用 `orchestration.json`，CLI 提供显式 `schedule/start/finish/recover`；这些不能证明原账本、自动接力、交付协调和本地网页兼容 | 以原运行合同、实际源脚本、网页和兼容性验证为准，替换冲突或误导的执行路径 |
| 验收实际迁移结果 | 现有模块测试证明各自实现的局部行为，不能证明源 Skill、脚本、网页和既有运行已完整迁入 | 建立源合同到实际资源、客户端入口和行为证据的逐项对应关系 |

以上偏差说明此前交付对象发生了缩减，不能归因于仅遗漏几个 `SKILL.md` 文件。当前源码和设计都须纳入纠偏；通过旧测试或保留原模块名称不足以完成修复。

## 消除错误实现的原则

先记录源合同与现有入口、模块、状态格式和测试的对应关系，再判断复用、替换或移除。可以复用经核实符合合同的进程、锁、原子写入、Codex 协议适配等底层能力；不得在未经核对的情况下整目录删除，也不得把已有独立客户端和 Go 工程一并重写。

与原迁移合同冲突的执行路径、错误的默认入口、缩水的完成判定和误导文档必须修正。删除或替换前定位准确文件和调用方，保留必要的兼容说明与恢复材料；既有用户状态不得因代码纠偏而被自动删除或覆盖。

## 验收要求

1. 29 套 Skill 在根目录 `skills/` 中真实存在，配套资源可解析，引用路径不依赖迁移来源机器的绝对路径。
2. 对应脚本及必要共享执行支持具有明确归属；在隔离来源目录的环境中验证，不以全局 dot-codex 恰好存在作为成功条件。外部能力按最终确认的依赖合同检测，缺失时明确说明适用阻塞。
3. 工程交付路径保留各自授权、停靠点和门禁，局部验证不能冒充完整交付完成。
4. 新运行覆盖派发、贡献完成、依赖解除、下一贡献接力、失败隔离、重启恢复和未知结果对账；不以静态任务图测试替代实际会话接力验收。
5. 既有运行的直接兼容性以代表性旧格式测试副本验证，覆盖状态保持与合法接续，禁止静默重置运行事实。
6. 本地网页及其后端资源纳入交付；验证更新与账本事实一致，不能只提供空页面或另起一套不兼容展示状态。
7. Bun 1.4.4 的测试覆盖真实迁入路径；不适用于跨平台的宿主能力明确标注，不伪造宿主接口或后台服务会话。
8. 修复清单明确列出被替换或移除的错误实现、保留模块及其依据；文档不再把简化模块验收等同于完整 Skills 迁移。
