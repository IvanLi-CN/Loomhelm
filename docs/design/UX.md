# Loomhelm UX 意图

## 文档职责与状态

本文记录 Loomhelm 在 D、Glass / Layered 方向下的长期桌面与手机 UX 意图、信息架构、交互不变量和状态语义；它不替代 [PRD](../PRD.md)、[核心规格](../specs/phase1-core/SPEC.md) 或公共合同。

主人已确认 `design/ui-language.html` 的 D 语言板及其桌面/手机、亮色/暗色配对示例；这确认材质、颜色角色、文字层级、控件状态和主题方向，不等于完整产品 UI 已获批准。

当前静态源包括 `design/layouts.html`、`design/layouts.css`、`design/layouts.js`、`design/layouts-tasks.css` 和 `design/layouts-tasks.js`；历史 18 张布局捕获曾覆盖工作台、会话工作区、任务列表/看板/图谱、手机信息面板与导航，当前 30 项定向合成检查和 10 张最终捕获的精确子集见 [HANDOFF](HANDOFF.md) 的“证据与当前限制”。这些都是合成演示证据，不是生产集成验证。

最终捕获与功能检查的覆盖范围、视口、合成限制和待完成边界见 [HANDOFF](HANDOFF.md) 的“证据与当前限制”；本文不固化临时证据路径或一次性检查摘要，也不等于完整产品 UI 已获批准。

本文以实际中文用户标签“工作台”“任务”“对话”“项目”为主；在需要对应产品合同或工程对象时，再使用 `Workbench`、`Tasks`、`Conversations`、`Projects`、Task、Session、Run 等英文语义标识。

## 当前静态源范围

`design/layouts.html` 当前提供“布局与体验”评审条、系统/亮色/暗色主题选择、场景菜单、桌面导航、主内容区、手机导航对话框、创建对话框、弹出菜单和无障碍状态播报容器。

`design/layouts.js` 当前提供合成的 Loomhelm、Sidecar Notes、Device Lab 项目和任务/对话/待介入事项数据；页面状态包含工作台、全部任务、项目工作区、全部对话和单个对话工作区，并提供项目树、对话叶子、工作台请求审阅、项目任务/对话切换、对话信息、草稿输入和绑定确认。

工作台静态范围包含“需要你介入”的待审批、需要输入和结果待核对事项，选中后展示完整请求、任务/项目上下文、命令预览、影响范围、批准/拒绝或对账入口，以及最近对话和“全部对话”入口。

任务页面静态范围包含搜索、业务状态筛选和列表/看板/图谱分段控件；`layouts-tasks.js` 负责列表表格、按业务状态分列的看板、带项目节点的关系图谱、父子层级与前置依赖边、图例、缩放和节点列表，`layouts-tasks.css` 负责这些视图的桌面/手机样式。窄屏工具栏把搜索与筛选排成两列，图谱摘要与缩放控件使用普通 grid row；当父任务属于外部项目时，renderer 同时保留父任务边并补画任务到其实际项目的归属边。本轮具体关系 fixture 为 Device Lab 项目的 `DL-08`，其父任务是 Loomhelm 的 `LH-30`，前置依赖是 Sidecar Notes 的 `SN-12`；Device 图谱应展示一个本地任务和两个带实际项目标签的已授权外部任务，任务信息/详情链接指向真实的任务与 Session 身份，并可进入项目范围图谱。

项目工作区静态范围包含项目标题、任务/对话两个面板和项目内全部对话；会话工作区静态范围包含主对话、任务信息 rail、手机“对话/任务信息”面板、子代理/工具折叠内容、对话文件、草稿、发送、绑定和中断请求。

脚本还包含正常、加载中、空状态、加载失败、离线、恢复连接、结果待核对、审批已过期、只读、权限已变更和有可用更新场景，以及主题、任务视图、草稿、阅读位置和演示决策的本地状态路径。切入或退出“权限已变更”会重新加载 mock 页面，草稿由 localStorage 保留，临时 mock-only 变更不写入服务端；这些都是合成演示状态，不能替代真实服务、权限、事件流、命令对账或 PWA 验收。

无项目会话上下文和导航都使用“对话”标签；信息面板中的“尚未归属项目”是属性说明，不是导航分组，不构成待解决的标签问题。

## 长期 UX 意图

### 1. 先让用户知道自己正在看哪一层

工作台（Workbench）是跨项目的默认工作入口，优先呈现待介入事项、完整请求上下文和继续工作的对话入口；正在运行不自动等于需要介入。

任务（Tasks）是跨项目的任务入口，展示同一批任务的列表、看板、图谱三种视图；切换视图不复制任务、不改变业务状态，也不改变执行状态。

对话（Conversations）位于全局入口下方，直接列出无项目的对话；项目（Projects）树为“项目 → 对话”，任务主对话和有项目但无任务的对话都直接成为叶子，不插入任务导航层。

从工作台的“全部对话”进入跨项目对话列表和创建路径；它不是额外的顶层导航项。进入具体项目后，项目工作区仍明确标出当前项目，并提供该项目的任务与对话两个面板。

每个页面的选中项、面包屑、范围提示和内容列表必须指向同一个实际对象；全局入口不能伪装成某个项目页面，项目标签也不能由任务父子关系推断。

### 2. 保持对话身份和绑定边界

独立对话可以在不选择任务或项目的情况下创建、发送和执行；项目选择是可选的，之后可以继续原对话并关联一个尚无主会话的任务。

每个任务至多一个主会话（Session），每个会话至多关联一个任务；绑定成功后保持固定，不提供解除、替换或跨项目迁移。UI 不应出现会暗示这些能力存在的按钮、菜单或“换绑”流程。

无项目对话在绑定前属于创建者私有；绑定时先展示历史消息、执行和文件将按目标项目权限共享的完整说明，再要求创建者明确确认。取消或失败时原会话、历史、文件、草稿和可见性全部保持原状。

绑定成功只改变任务关联与项目归属；原有消息、执行记录和文件引用仍属于同一段历史，不能因为关联了任务就替换对话正文或补造子代理、工具与文件记录。

历史共享不等于草稿共享；未发送的共享草稿始终只在创建者自己的已授权客户端之间同步，即使对话历史已经进入项目，也不能向其他项目成员暴露。

### 3. 让执行事实先于视觉反馈

任务业务状态与执行、审批、连接和控制状态必须分开呈现；一次执行完成不得自动把任务标记为完成。

审批卡片先展示完整请求、影响范围、关联项目/任务、当前版本和相关对话上下文，再提供明确的批准/拒绝；当前版本已过期、已处理或已撤销时操作控件必须禁用，并显示实际结果。

已处理的审批不再计入待介入数量；保留选中的原请求供核对时，列表与详情必须使用一致的已处理提示。如果只知道请求已失效，执行结果仍未收到，就显示执行状态待更新，并保留进入原对话的路径；不能据此推断已批准、已拒绝或执行结束。

命令状态至少要区分已接收、已开始、等待审批、已结束、连接断开和结果不确定；“中断请求中”（interrupt pending）是等待实际终止观察的中间状态，不得画成“已中断”这一终态。

当命令副作用无法确认时显示结果不确定（unknown），提供对账（reconcile）、继续调查或人工处理路径；恢复必须先对账，不能把重试设计成无条件重放，也不能因为 ACK 丢失而盲目重复操作。

发送始终是明确动作；编辑同步、页面恢复、联网恢复和 PWA 更新都不能发送或排队发送。离线时可以继续阅读和恢复草稿，但控制命令不可离线排队、后台补发或自动重放。

### 4. 让多端连续工作而不发生设备接管

同一主人的多个 Web/PWA 客户端共享已提交的任务、会话、执行、事件和操作状态，但不存在接管；第二个客户端不因打开同一对话而变成只读观察者。

各客户端独立保留当前页面、选中对话、任务视图和阅读位置；一台设备的导航、滚动和面板切换不得移动另一台设备的浏览位置。

共享草稿冲突自动采用一致排序下的最后一次修改，不要求用户在冲突副本间选择；发送只消耗实际发送的文本，并保留之后产生的新输入。草稿恢复永远不发送。

检测到 PWA 更新时，更新提示、应用更新和重连过程都必须保留当前对话、任务、草稿、面板、展开分支和阅读位置；旧资源与事件位置的兼容性由工程合同负责，UI 不能假设刷新就是安全恢复。

### 5. 让图谱表达关系而不泄露权限

图谱必须同时表达两种不同关系：任务层级/包含关系与有方向的前置依赖；它们使用不同的线型、箭头或图例，不能用同一种边让用户猜语义。

列表、看板、图谱引用同一批任务身份；图谱中打开节点进入同一个任务工作区，不能生成副本或隐藏任务状态与执行状态的区别。

相关节点必须按真实返回的项目标签展示；不能因为父子关系把外部任务伪装成本项目任务。无权访问的外部节点不得通过标题、预览、文件、状态或边上的提示泄露内容，必要时只保留不泄露信息的结构反馈或完全不显示。

父提交 `079d3d85318c365056cd29a238aafdf732581421` 的 PRD/SPEC 已确认任务层级与前置依赖是两种独立关系，均可跨项目；每个任务保留自己的项目归属，关系变更必须在两端执行授权，关系不能向未授权任务或项目授予访问权，也不能泄露受保护内容。自环与循环是否拒绝、关系编辑与删除的精确语义，以及团队成员权限仍由主协调者收敛；本文只固定已确认的展示与不泄露边界。

### 6. 在 D 材质中保持内容可读

D、Glass / Layered 的亮色与暗色必须使用相同的信息层级、语义状态和操作能力；只切换配对的 material、ink、line、highlight、accent、warning、success、danger 角色，不另造一套主题布局。

玻璃用于导航、结构层和浮层；阅读面、长消息、代码、审批详情和任务信息应保持足够不透明。层次优先通过色调、细边界、内高光和有限阴影表达，不能用持续的大面积模糊或高光干扰阅读。

延续 [DESIGN.md](DESIGN.md) 的现有尺寸和语义：桌面按钮约 38px、输入/选择控件约 42px，手机交互目标至少 44px；状态必须同时有文字、图标或几何差异，不能只依赖颜色。

## 桌面与手机布局映射

下表记录布局意图、静态源映射和当前覆盖边界；合成浏览器证据与仍待合同/生产验证的范围见 [HANDOFF](HANDOFF.md)。

| 场景 | 桌面布局意图 | 手机布局意图 | 不变的能力与语义 |
| - | - | - | - |
| 全局壳层 | 保留项目/对话树、当前范围和主工作区；导航树可折叠，内容面保持稳定 | 用导航抽屉承载同一棵树，顶栏显示当前范围与返回路径 | 工作台、任务、对话、项目的层级和实际归属一致；没有主机或独立产物入口 |
| 工作台 | 左侧上下文树，主区先放短待介入列表与相邻的完整请求审阅，下面放最近对话和“全部对话” | 依次阅读待介入列表、完整请求、最近对话；完整请求不藏在只有图标的二级入口里 | 先展开完整请求再批准/拒绝；异常、权限、失效和执行中状态可区分；创建对话可不选项目/任务 |
| 任务 | 全局范围的视图工具栏与内容区，列表、看板、图谱共享任务身份；适合并列比较和持续浏览 | 保留同一三视图切换，搜索/筛选使用两列工具栏，列表/看板可纵向滚动，图谱在窄屏保持可缩放和可平移 | 视图偏好按客户端、工作区、范围记忆；首次为列表；任务业务状态不被执行状态覆盖 |
| 项目工作区 | 当前项目的任务与对话两个面板；对话面板含该项目全部对话，树叶直接落到对话 | 以项目范围的局部面板或分段切换呈现任务/对话，保留项目标题和面包屑 | 无项目对话不被伪装成项目对话；任务主对话与无任务项目对话同级可达 |
| 任务工作区 | 主对话为阅读和输入区，右侧信息 rail 放目标、任务状态、绑定和执行信息；子代理活动在主会话内展开 | 在同一个任务工作区内切换“对话/任务信息”面板；关系信息可滚动，切换不清空草稿、不改变阅读位置 | 桌面/手机能力一致；审批、拒绝、中断、结果不确定、文件引用、草稿和任务信息都留在对应上下文 |
| 绑定流程 | 在对话上下文中打开关联流程，完整解释历史共享和目标项目权限 | 使用可返回的局部 sheet/dialog，不丢失当前对话和输入 | 只允许未绑定会话与无主会话任务；无替换、解除、跨项目迁移；草稿继续私有 |
| 图谱关系 | 通过图例、不同边样式和项目标签并列阅读层级与依赖；外部父任务同时保留父任务边和实际项目归属边 | 保留图例、缩放、平移和节点详情；图谱摘要与缩放保持正常 grid 流，避免控件重叠 | 关系语义独立；权限过滤先于渲染；无权节点不泄露标题、预览、文件或项目细节 |
| 更新/断线 | 顶部或上下文区明确显示恢复连接、离线、更新，保留正在读的工作面 | 使用同等明确的连接与更新提示，恢复后回到原面板 | 不自动发送、不离线排队、不盲目重放；草稿和上下文保护与桌面一致 |

## 状态与动作矩阵

这张矩阵定义页面应该让人知道什么、可以做什么以及什么必须禁止；它不定义 API 路径、请求字段或事件名称，具体公共合同以后以 F05 为准。

| 状态 | UI 必须表达 | 可用动作 | 明确禁止或后置条件 |
| - | - | - | - |
| 加载中（Loading） | 当前范围和对象正在加载，避免用合成内容冒充历史 | 等待；读取失败后按实际结果重新读取 | 不展示已执行、已批准或已绑定的假事实 |
| 空状态（Empty） | 当前范围为空以及下一步入口，例如创建对话或任务 | 创建、进入可用范围 | 不把空态改成“暂无权限”或反过来 |
| 无项目独立对话 | 对话范围、私有归属、可执行的独立会话 | 阅读、编辑草稿、明确发送、审批/拒绝、中断、以后发起绑定 | 不要求先建任务；不向项目成员暴露历史或草稿 |
| 等待历史共享确认 | 目标项目、将共享的历史/执行/文件、草稿仍私有 | 明确确认后绑定，或取消返回原对话 | 未确认不得改变项目归属、权限或会话身份 |
| 可绑定/已占用 | 会话与任务的实际占用情况 | 仅对未绑定会话和无主会话任务展示绑定动作 | 不提供替换、解除、跨项目迁移；失败保留原状态 |
| 当前审批 | 完整请求、影响范围、上下文、当前修订和等待人工决定 | 逐项展开后批准或拒绝 | 不用摘要代替完整请求；不允许恢复/加载期间的隐式批准 |
| 过期/已处理审批 | 已过期、已撤销或已处理的实际结果 | 查看当前状态、进入对话或等待新请求 | 批准/拒绝必须禁用；重复点击不能重新授权 |
| 已接收/执行中 | 已接收与已开始、等待审批、执行结束等阶段的区别 | 按真实能力继续查看、审批、拒绝或请求中断 | 不把队列完成、执行完成或页面离开当成任务完成 |
| 中断请求中（interrupt pending） | 请求中断已提交但终止尚未被实际观察到 | 查看事件、等待对账、在明确路径下继续调查 | 不显示为已终止；不重复发送中断命令 |
| 中断终态 | 已观察到终止、失败或其他真实终态 | 查看结果，按会话当前能力继续交流 | 不保留“正在请求中断”的误导性操作 |
| 结果不确定（unknown） | 副作用是否发生尚未确定，命令身份和已知事实仍可追踪 | 对账、继续调查或进入人工处理 | 不自动重试、不盲目重放、不用成功/失败颜色掩盖不确定 |
| 离线/恢复连接 | 当前连接能力、上次已知状态和草稿可恢复性 | 阅读、编辑草稿、等待重连 | 控制命令不可离线排队、补发或自动重放 |
| 草稿冲突 | 最后一次修改已胜出，必要时给出非阻塞同步反馈 | 继续编辑，明确发送当前内容 | 不要求选择冲突副本；发送不清除之后的新输入 |
| 只读/权限改变 | 内容可见性和当前权限事实清楚，控制入口按权限收紧 | 继续读取授权内容，按实际结果返回 | 不能只靠隐藏按钮模拟授权；不得加载越权详情或文件 |
| PWA 有可用更新 | 新版本、当前上下文和待保留输入清楚 | 明确应用更新，重连后恢复 | 不静默丢草稿、任务、会话、面板或阅读位置 |

## 合成 Demo 的边界

`design/ui-language.html` 是已确认的 D 语言板，`design/layouts.html` 是当前静态布局演示；最终浏览器捕获确认的是合成演示的布局与交互，不是生产导航、权限、事件流、执行、文件下载、跨端同步或 PWA 行为。

布局脚本的主题、场景、草稿、阅读位置、视图偏好、批准/拒绝、中断请求、绑定和创建行为只更新本地演示状态；它们不调用产品 API，也不证明命令已接收、授权已生效或对账已完成。

任务三视图与图谱关系已有静态 renderer；数据仍是合成的，不能证明跨项目关系合同、服务器授权或生产外部节点隐私。本轮“权限已变更”场景在构造 UI 前过滤 Sidecar Notes 范围，并从 `parentId`/`dependsOn` 移除无权任务引用，不保留受保护任务的轮廓、数量、标题、状态或项目元数据；原始 fixture 仅是合成代码。当前合成结果记录为正常 Device 图谱 4 条层级关系（含项目归属）加 1 条依赖关系，权限场景 3 条层级关系且 Sidecar 不出现在 DOM；项目范围 list/board 功能检查通过，新捕获聚焦 graph 与关系信息。
