# Loomhelm 产品需求说明

## 1. 文档职责与确认边界

本文是 Loomhelm 的完整产品需求入口，说明产品方向、一期范围、用户场景、业务规则和验收标准。主线程负责整理与维护，主人负责产品取舍和范围确认；唯一的 UI 设计任务负责将需求转化为信息架构、原型、视觉、组件状态和实现交接。设计访谈产生的产品结论回到本文，接口与实现不得自行创造另一套业务规则。

本文汇集已批准的开发范围和主人在设计访谈中确认的结论，整份 PRD 尚待主人确认。第 12 节的建议没有因写入文档而获得批准。现有原型、工程骨架和技术研究也不代表产品能力已经实现或验收。

业务功能开发和公共业务接口定稿以主人明确确认一期 PRD、且相关业务问题已经收敛为准入条件。产品 UI 实现还需主人确认完整 UI 设计。工程骨架、开发环境、质量与发布基础设施、Codex 能力验证，以及当前同一个 UI 任务内的需求和设计讨论可以并行推进。

[工程规格](specs/phase1-core/SPEC.md)承接本文中已确定的行为约束与验证编号；接口、状态机和数据模型实现细节由工程规格及其合同描述。二者冲突时先由主线程回收产品决定并同步，不由实现者选择其一。实现覆盖与能力证据记录在工程规格的配套文档中，不以本文作为完成记录。

## 2. 产品定位与问题

Loomhelm 是面向个人与小型团队的自部署项目管理与 Agent 工作台。用户在同一个 Web/PWA 中管理工作目标、查看 Codex 执行、处理审批并获取结果，既能通过浏览器操作，也能让获授权的 Agent 通过 API/MCP 操作相同业务。

当前需要解决的问题是：项目与任务管理、Codex 桌面对话、执行控制和结果文件分散在不同入口；人在手机与电脑之间切换时缺少连续工作上下文；任务业务进度与 Agent 实际执行状态容易混淆；远程操作遇到断线、重启或发布时难以判断是否已经执行。

长期方向是“主 Agent 管理全局、项目 Agent 管理项目、Task Agent 完成具体工作”，主人通常与主 Agent 沟通，也可以直接查阅和干预其他 Agent。一期先交付真实可用的项目、任务、对话和监督执行基础，不将上述自动编排体系作为已经具备的能力。

## 3. 用户与使用场景

| 用户或参与方 | 一期需要完成的事情 | 边界 |
| - | - | - |
| 主人 | 从电脑或手机管理任务、发起和查看对话、处理审批、中断执行、取回结果 | 同一身份可以多端同时工作，无须设备接管 |
| 获授权的小团队成员 | 在获授权项目内查阅和操作工作 | 跨项目访问受到限制，具体成员操作矩阵见第 12 节 |
| 获授权的 API/MCP 调用方 | 创建和更新项目任务、操作对话、处理审批、查询结果 | 与 Web 共享应用服务、权限和幂等规则；不绕过人的批准边界 |
| 部署维护者 | 配置单一执行环境、管理 Connector 凭据、部署与恢复服务 | 属于部署管理，不形成产品中的主机管理模块 |

典型场景包括：从已有任务启动开发；先独立研究再将对话关联任务；远程接入桌面上正在进行的同一个 Codex 对话；从工作台处理待批准操作；手机接续电脑上的未发送草稿；发布或断线后确认执行结果并继续工作。

## 4. 产品目标与成功标准

| 目标 | 一期可观察的成功结果 |
| - | - |
| 工作与执行连在一起 | 项目、任务及其主对话可以相互定位，任务业务状态和执行状态各自清楚 |
| 不要求先建任务才能交流 | 用户可直接新建独立对话，项目可选；之后关联任务时继续原对话 |
| 主人能够监督真实执行 | 新建和现有桌面活跃对话两条路径均可实际收发、审批、拒绝和中断 |
| 多端连续工作 | 已提交状态与未发送草稿同步，各端导航和阅读位置独立 |
| 故障结果可判断 | 命令可去重、事件可恢复，无法确定的副作用明确显示为 unknown，不自动重复执行 |
| 自部署与迭代可持续 | 工程检查、持久化、早期蓝绿和完整业务切换演练具备实际证据 |
| 人与 Agent 使用同一产品 | Web/API/MCP 完成真实后端闭环，权限和错误语义一致 |

成功判定以第 11 节的场景验收为准；可编译、原型演示、历史读取或仅有协议文档都不能代替真实运行。

## 5. 一期范围与优先级

表中的“一期必须”均是交付范围，不因工程拆分而推迟到后续阶段。依赖外部能力的内容仍需证明，不能以弱化实现替代。

| 范围 | 优先级 | 交付内容 |
| - | - | - |
| 项目与任务 | 一期必须 | CRUD、业务状态、项目权限、任务层级与前置依赖、列表/看板/图谱 |
| 工作台与项目上下文 | 一期必须 | 全局工作台、任务、对话入口，项目/具体项目/对话导航树，无项目对话入口，待介入事项 |
| 对话与任务关联 | 一期必须 | 独立对话、可选项目、稍后关联任务、每任务至多一个主对话 |
| Codex 双路径控制 | 一期必须 | 指定的单一执行环境中新建对话，以及控制桌面现有活跃对话 |
| 执行与人工监督 | 一期必须 | 发送、事件流、审批/拒绝、中断、异常和控制冲突反馈 |
| 可靠性与多端 | 一期必须 | 命令去重、持久事件、断线/重启对账、共享草稿、各端独立视图 |
| 对话内容与文件 | 一期必须 | 基础消息/代码/工具状态、可用的子代理事件、未知内容回退、真实文件下载 |
| 接口 | 一期必须 | Web、HTTP API、MCP 使用真实应用服务 |
| Web/PWA | 一期必须 | 桌面与手机能力一致、安装、离线外壳、受控更新和上下文恢复 |
| 工程与交付 | 一期必须 | 可复现开发、质量门禁、独立进程、持久化、业务开发前的蓝绿机制及演练 |

一期不包含自动主/项目/任务 Agent 编排、自治运维、自动验收、完整 Codex 桌面内容格式复刻、任意 HTML/MCP Apps 插件宿主、复杂文档转换、插件市场、多执行环境管理、远程文件系统浏览器、Kubernetes、多机高可用、离线执行控制或未经确认的 UI 扩展。

正式版本、生产身份配置、生产部署和最终父 PR 合并保留给主人决策。本期验收使用隔离环境和候选产物，不自动发布生产。

## 6. 核心对象与关系

| 对象 | 产品含义 | 关键规则 |
| - | - | - |
| 项目 Project | 组织任务和已归属项目的对话，并作为权限范围 | 全局入口聚合有权访问的数据，不扩大项目权限 |
| 任务 Task | 一项可持久管理的工作目标 | 有独立业务状态；子任务仍是任务，每任务至多一个直接关联的主对话 |
| 对话 Session | 与实际 Codex thread 对应的连续交流上下文 | 可以先没有任务、没有项目；之后关联任务保留同一对话身份 |
| 执行 Run | 对话中的一次执行尝试 | 对应实际执行及事件，可有多个；独立对话也可执行，不能要求所有 Run 先有 Task |
| 控制命令 Command | 发送、审批、中断等一次明确操作意图 | 使用稳定标识，区分平台接收、实际执行、结束与结果不确定 |
| 审批 Approval | Codex 请求人明确决定的一项操作 | 绑定实际请求及当前修订，重复点击或旧页面不能再次授权 |
| 对话文件 | 消息提及或执行产生的原始文件及元信息 | 保留对话上下文与授权下载，不形成单独的文件管理模块 |
| 共享草稿 | 同一主人多端共同可见的未发送输入 | 同步不等于发送，恢复不自动变成执行命令 |
| 子代理活动 | Codex 对话内委派工作的可观察活动 | 只展示实际协议支持的事件，不自动建立平台子任务或额外主对话 |
| 执行环境 | 当前安装预配置的一个逻辑 Codex 执行入口 | 物理机器可与平台不同，产品无需主机选择器 |

任务包含关系和任务前置依赖是两类不同关系。列表、看板、图谱展示同一批任务；切换展示方式不创建任务副本，也不改变业务状态或执行状态。

一次 Run 的完成、中断或失败不自动证明任务已完成。任务与执行状态应分别呈现；需要自动联动的行为必须另有明确产品规则。

“每个任务至多一个主对话”只确定 Task 到 Session 的约束，尚未确认同一个 Session 是否可以关联多个 Task。不能据此私自选定反向基数、替换或解绑规则。

## 7. 信息架构与页面职责

| 入口或工作区 | 数据范围 | 主要职责 |
| - | - | - |
| 工作台 | 当前用户有权访问的全局范围，含有权访问的独立对话 | 优先处理待审批、异常及其他需要人工介入的事项，提供对话入口 |
| 全局任务 | 所有有权访问项目中的任务 | 跨项目查看目标和进度，切换列表/看板/图谱 |
| 全局对话 | 当前用户有权访问的对话，包含独立与任务对话 | 新建独立对话、查看活动、进入已有对话 |
| 项目导航树 | 项目分组 → 具体项目 → 该项目对话 | 可折叠，任务主对话与无任务的项目对话都直接成为对话叶子，不插入任务导航层 |
| 无项目对话分组 | 有权访问且尚无项目的对话 | 直接进入独立对话，避免只通过全局搜索或任务才能找到 |
| 项目工作区 | 选定项目 | 提供任务/对话两个面板；对话面板包括该项目的全部对话，保持面包屑、选中项与范围一致 |
| 任务工作区 | 选定任务及主对话 | 在同一上下文查看目标、业务状态、执行、输入和子代理活动 |
| 独立对话工作区 | 选定独立对话 | 直接交流和监督执行，之后可关联任务 |

工作台默认突出待介入事项，正在运行本身不等于需要介入。审批须能先展开完整请求、影响范围及相关上下文，再明确批准或拒绝，并可进入完整对话。

桌面可将对话与任务信息并列；手机在同一个任务工作区内切换相应面板并保留草稿与阅读位置。具体布局、视觉、交互和状态由同一个 UI 设计任务完成并由主人确认。

不设置主机管理、主机选择器、全局产物页面、任务产物侧栏或手机产物面板。文件入口位于相关对话与消息中。以上产品边界不取消内部 Connector 管理和文件持久化服务。

## 8. 功能需求

### PRD-LH-001：项目、任务与关系

用户能够通过 Web/API/MCP 创建、读取、修改和删除项目与任务；数据持久化，刷新和服务重启不丢失。项目应能表达名称与说明，任务应能表达标题、目标说明、所属项目和业务状态；精确字段、校验和状态枚举在公共合同中确定。

项目范围权限覆盖任务、层级、依赖及其关联结果。删除操作遇到活跃执行或需保留的历史结果时必须得到明确受保护的结果，不能静默遗失归属或级联删除执行证据。跨项目关系、状态枚举及删除策略的建议集中在第 12 节。

全局与项目范围都提供列表、看板和图谱。列表支持紧凑展示、按业务状态筛选或分组；看板按业务状态组织；图谱区分项目/任务/子任务包含关系与有方向的前置依赖。关系的建立与移除通过同一应用服务持久化；一期不默认承诺图谱拖拽编辑、自动排期或依赖完成后自动执行。

每个客户端分别记住全局任务和各项目的视图选择，首次默认列表。客户端本地、按身份/工作空间/范围隔离的偏好存储是当前工程默认，不要求建设服务端偏好中心，也不让另一设备的切换改变当前视图。

### PRD-LH-002：工作台与导航

全局导航包含工作台、任务、对话，另外提供可折叠的“项目 → 具体项目 → 对话”导航树。树中的对话叶子同时包含任务主对话与有项目但没有任务的对话，不在项目和对话之间插入任务层级；无项目对话另有直接可达的分组。这是导航结构，不是新增多级项目业务模型。

项目工作区有任务和对话两个面板，对话面板展示有权访问的该项目全部对话。项目内创建对话预选当前项目，全局创建仍可不选项目。新建和后续关联任务时，树归属、选中项与面包屑使用同一实际对话与范围。进入某个项目不能将全局入口伪装成该项目的同一页面。

工作台聚合获授权的待介入事项。用户可以查看相关项目/任务或独立对话、定位异常、展开审批并在上下文中操作。无权限、已失效或已处理的事项不能继续提供有效控制入口。

### PRD-LH-003：独立对话与任务主对话

用户可以从全局对话入口新建独立对话，不必先创建任务，也可以暂不选择项目。独立对话应具有实际输入、执行、审批、中断和结果访问能力，不能只是一个静态备注或必须先绑定任务才能发送的占位页。

对话之后可以关联已有任务或在创建任务后关联。原本没有项目的对话归入目标任务的项目；关联继续原对话，消息、事件、已发生的执行、文件引用、共享草稿和客户端上下文不能因复制或重新创建 Session 而丢失。全局与项目列表引用相同身份，不生成第二份对话。

关联必须进行授权与一致性检查，失败时保留原有对话。每任务至多一个主对话。跨项目移动、已占用任务的处理、反向基数以及历史可见范围仍按第 12 节收敛；原型当前只展示未占用目标，不构成这些规则已经确认。

### PRD-LH-004：Codex 双路径接入

路径一是在预配置的执行环境中创建真实 Codex 对话。路径二是接入同一执行环境中桌面版正在活跃的同一个 thread/turn，支持读取事件、发送、审批/拒绝、中断，以及连接中断后的状态对账。

接入现有对话必须保留实际身份。历史查询、复制线程、fork、在独立 app-server 中恢复相似内容或通过 Codex 私有 UI 桥接发送消息，均不能单独证明可供 Go Connector 复用的桌面活跃会话控制能力。

桌面双路径属于一期必须能力，目前既有活跃会话的通用接入仍未实测成立；如无法证明，公开报告为交付阻塞，不能默认缩减为单路径或假造“已连接”。登录、身份挑战和额外权限需要主人实际参与。

### PRD-LH-005：执行、控制与恢复

用户能明确发送输入，查看消息与工具活动，并区分控制命令已接收、Codex 已开始、等待审批、执行结束、连接断开和结果不确定。具体运行状态机由合同定义，但不能把队列作业完成等同于 Codex 完成。

发送、审批和中断携带唯一命令标识与适用修订。平台和 Connector 持久记录后确认接收；同一操作的重试返回同一操作事实。重启或 ACK 丢失后先对账，无法确认副作用是否发生时显示 unknown，并提供继续调查或人工处理路径，不盲目重放。

中断是对当前实际执行的请求；页面应区分“正在请求中断”和“已观察到终止”。原生桌面直接操作可能改变执行状态，平台需依靠实际事件和状态对账更新，不能假设自己是唯一操作入口。

### PRD-LH-006：审批与并发控制

审批展示真实请求、上下文及影响范围，并提供明确批准和拒绝。操作针对对应请求及当前版本，已经回答、已撤销或过期的审批不能再次批准。并发响应应有确定结果；失败、失效和无权限须可辨认。

同一主人的多个客户端可同时工作。平台的执行控制协调保护命令一致性，不要求主人在手机与电脑间进行设备接管，也不将第二个客户端降为只读。实际无权限、连接不明确和控制冲突仍需有对应状态。

### PRD-LH-007：共享草稿与客户端连续性

同一主人的已授权客户端能看到并接续同一个对话的未发送草稿，同时同步已提交的任务、对话和操作状态。发送必须是独立的明确动作；编辑同步、页面恢复或联网恢复都不自动发送。

各客户端的当前页面、选中对话、阅读位置和任务视图保持独立。一个客户端切换项目、打开对话或滚动消息，不移动另一客户端。每个订阅者独立恢复其事件位置。

并发编辑、离线草稿恢复与发送后的草稿处理必须有明确规则，不能默默覆盖未发送内容或依赖不可见的最后写入覆盖。是否只支持单编辑者、如何展示冲突及保留内容见第 12 节；一期不默认扩展为完整协同文档编辑器。

### PRD-LH-008：内容、子代理与对话文件

一期可读地显示基础消息、代码、工具及审批状态。对无法识别的类型提供清楚的回退，并保留原始字段用于后续兼容。未知结构不能使整个对话不可读，也不能执行未经约束的 HTML 或脚本。

有真实事件支持时，在主对话中展开子代理工作、状态、结果及可用消息/工具活动。子代理不会因此自动成为平台子任务或额外任务主对话。没有协议数据的详情不得用 mock 推定为真实能力。

文件保留原始字节、元信息与会话/消息关联，通过真实授权接口查询和下载，重启及蓝绿切换后仍可取回。文件名、路径或原始事件不得绕过项目或独立对话的访问规则；关联任务前的文件也需要受到保护。下载失败、不可用或无权限须有明确反馈。远程文件系统浏览不在一期。

### PRD-LH-009：身份、权限与调用凭据

Web 登录采用 OIDC、HttpOnly 会话与 CSRF 防护。API/MCP 使用可撤销的用户凭据，Connector 使用独立的部署凭据；权限校验进入共享应用服务，不能只依赖前端隐藏按钮。

项目访问规则覆盖任务、关系、命令、审批、事件、草稿与文件。无项目对话需要明确创建者归属和访问范围；加入项目涉及历史内容权限变化，必须在产品规则确认后落地。全局聚合、长连接、重连和下载也要持续遵守凭据撤销与授权范围。

Codex 登录凭据留在执行机器，不上传平台或发送给浏览器。配对、认证、凭据撤销和连接状态属于安装管理，不形成多主机产品。团队成员角色、独立对话私有范围和加入项目后的历史可见性见第 12 节。

### PRD-LH-010：Web、API 与 MCP 一致性

三个入口调用同一应用服务，提供项目任务与关系、对话关联、实际控制、审批、事件及对话文件能力。内部可保留执行环境或 ArtifactStore 等技术对象，但不因此引入公开主机列表或独立产物模块。

API/MCP 不得成为权限、确认、版本或幂等约束的旁路。未知结果、过期审批、重复命令和关联冲突在各入口使用一致的业务含义。具体端点、工具名、传输与类型生成由公共合同描述。

### PRD-LH-011：Web/PWA 与移动端

产品是可安装的响应式 Web/PWA，桌面与手机具有相同的一期能力。关键流程须支持窄屏、键盘和可辨认的焦点、状态及错误，不能仅靠颜色传达执行或审批状态。

离线时展示离线外壳和明确连接状态。敏感 API 响应不进入 Service Worker 的通用离线缓存；控制命令不离线排队、后台补发或恢复后自动重放。未发送草稿能否本地恢复及其冲突反馈须遵循已确认规则。

检测到更新时告知用户并受控应用，不突然丢弃输入、当前对话和阅读上下文。部署保留兼容客户端需要的旧静态资源；客户端重连后按持久事件位置恢复。安装与更新使用真实浏览器场景验收，manifest 或构建产物存在不足以证明可安装。

### PRD-LH-012：自部署、持久化与蓝绿发布

后端使用 Go/chi，Server、Worker、Connector 分进程；数据使用 PostgreSQL、pgx/sqlc、goose，River 用于短派发和对账。前端采用 React/Vite/TypeScript、Bun workspaces、TanStack Router/Query、shadcn/Tailwind 和 Storybook；Bun 是前端工程工具链。

开发环境可复现，配置不覆盖已有本地文件，错误明确。代码、类型、有效范围测试、生成漂移、数据库/作业、启动和部署检查真实运行，失败不能被占位脚本吞掉。重型验证在会话 VM 内执行。

自部署交付包含安装与配置、身份接入、单一执行环境接入、启动/停止、凭据撤销、升级、备份恢复和故障排查说明。配置及持久化路径清楚可查，缺失必需配置时给出可处理的错误；不代替主人写入生产环境。备份恢复与兼容窗口内的应用切回是不同操作，分别说明并验证其适用条件。

业务迭代开始前建立并实测蓝绿管线。候选绑定准确源码 SHA、digest、配置与迁移状态；构建一次后晋级。Caddy 负责双槽健康检查与切流，Server drain、Worker generation/fencing、Connector 对账分别验证。

数据库和文件跨槽持久化，旧 Worker 不得继续以失效 generation 调度。仅在已经证明的状态兼容窗口内切回；应用切回不自动逆转数据迁移，窗口外以前向修复处理。之后复用同一管线验证真实执行与完整产品，不能只以早期空服务演练代替最终验收。

## 9. 关键用户旅程

| 场景 | 操作过程 | 应有结果与异常边界 |
| - | - | - |
| 从任务开始 | 登录 → 创建项目/任务 → 打开任务工作区 → 新建或关联主对话 → 发送工作 | 刷新后任务和对话身份保留；执行状态不覆盖任务业务状态 |
| 先研究再归档 | 全局对话 → 暂不选项目创建 → 实际交流/执行 → 关联已有或新建任务 | 延续同一对话及内容；无项目对话归入任务项目，权限变化按确认规则处理 |
| 接续桌面活跃工作 | 打开已有对话接入 → 验证真实 thread/turn → 读取与发送 → 审批/拒绝或中断 | 操作的是同一实例；不可用时明确阻塞，不复制替代 |
| 处理待介入事项 | 工作台 → 展开完整请求与上下文 → 批准/拒绝 → 查看执行后续 | 已处理或过期请求停止提供有效按钮；重复点击不多次授权 |
| 多端继续输入 | 电脑编辑 → 手机上打开同一对话 → 继续草稿 → 明确发送 | 草稿同步不自行执行，各端阅读和选中页面保持独立 |
| 断线与重启 | 已提交控制 → 网络或进程中断 → 重连 → 事件恢复和命令对账 | 区分已接收与已执行，不确定则显示 unknown，不产生盲目重复操作 |
| 获取结果 | 对话消息 → 查看文件引用 → 授权下载 → 重启/切换后再下载 | 字节和引用连续，越权、路径越界和凭据撤销得到拒绝 |
| 应用更新与发布 | 有上下文的 PWA → 提示新版本 → 用户更新 → 重连 | 上下文和未发送输入得到保护，旧资源兼容，不重放控制命令 |

## 10. 非功能需求

| 维度 | 一期要求 | 验证方式 |
| - | - | - |
| 数据正确性 | 任务、对话、命令、事件与原始文件持久化；并发和重试得到确定结果 | 真实数据库、文件字节比对、进程重启与故障注入 |
| 安全与隐私 | 服务端统一授权、凭据隔离与撤销、CSRF、路径约束、不可信内容处理；日志不泄漏凭据 | 越权/失效凭据/恶意路径和内容用例，脱敏检查 |
| 可恢复性 | 独立事件位置、对账、可见 unknown；发布不使执行被重复派发 | 丢 ACK、断线、Server/Worker/Connector 重启、蓝绿交接 |
| 可用性 | 加载、空态、错误、无权限、离线、冲突及待确认状态可辨认；操作反馈基于实际结果 | 桌面/手机关键路径与受控交互证据 |
| 内容增长 | 任务与长对话采用有界查询或增量加载，恢复流不依赖无限整页重放 | 使用代表性数据量观察响应和内存；不在无基准时承诺吞吐数字 |
| 可访问性 | 主要操作可用键盘完成，焦点可见，状态有文字含义，手机上能完成同等操作 | 关键路径键盘、窄屏与状态检查；不以此宣称完整标准认证 |
| 可观察性 | 命令、Run、Connector 连接、候选和迁移具有可关联身份，能解释失败与恢复 | 脱敏日志和持久事件可定位同一操作，不仅依赖 UI 提示 |
| 兼容性 | 实际 Codex 版本、传输和双路径分别记录证据；未知事件保留；状态兼容窗口明确 | 真实协议样本、相同 thread/turn 核对和候选切换 |

一期未承诺公网服务 SLA、大规模并发、多租户组织体系、所有浏览器一致的 PWA 安装入口或任意 Codex 版本兼容。验收需记录实际桌面/手机浏览器、Codex 与部署版本，不以未验证平台作兼容承诺。

## 11. 验收标准与交付定义

以下场景使用真实后端、真实 Codex 和实际候选运行。mock 只用于确定性测试和 UI 原型，不能代替观察证据。涉及第 12 节建议的场景按主人最终确认后的规则执行。

| 编号 | 给定与操作 | 通过条件 | 需求映射 |
| - | - | - | - |
| AC-LH-001 | Web/API/MCP 对项目任务和关系 CRUD，刷新并重启数据库连接/服务 | 结果持久且一致，越权被拒绝，活跃执行和保留结果的删除有保护 | PRD-LH-001、009、010 |
| AC-LH-002 | 在全局和项目范围切换三种任务视图，展开项目/对话树及无项目分组，创建有/无项目、有/无任务的对话，再刷新及从另一设备导航 | 相同任务身份与独立关系一致，任务视图偏好按范围保留；项目对话叶子和无项目入口完整可达，面包屑与预选项目准确，各端视图独立 | PRD-LH-001、002、003、007 |
| AC-LH-003 | 不选任务和项目创建真实对话、发送并产生文件，再关联任务 | 同一 Session、消息、Run、事件、文件与草稿连续；加入项目后的权限符合确认规则，无副本和无授权泄漏 | PRD-LH-003、005、007、008、009 |
| AC-LH-004 | 在指定环境新建实际 Codex 对话 | 可收发、观察事件、实际批准/拒绝、中断并恢复，不止历史读取或 mock | PRD-LH-004、005、006 |
| AC-LH-005 | 接入专用桌面现有活跃对话，对同一 thread/turn 操作后断开并恢复 | 同实例读写、审批/拒绝、中断与对账均有证据；复制或另开实例不通过 | PRD-LH-004、005、006 |
| AC-LH-006 | 重复命令、并发审批、过期响应、ACK 丢失，分别重启三个进程 | 不重复授权已完成操作，结果确定或显式 unknown，能依据持久事实恢复 | PRD-LH-005、006 |
| AC-LH-007 | 同一主人电脑和手机同时编辑/查看对话，再断线、恢复和发送 | 共享草稿按确认规则恢复且不静默丢失；同步不发送，各端视图独立，无设备接管 | PRD-LH-006、007 |
| AC-LH-008 | 在有/无权限、凭据撤销和越界路径下下载真实文件，重启后再取回 | 授权对象字节一致，拒绝无权访问，对话上下文和保留结果不丢失 | PRD-LH-008、009 |
| AC-LH-009 | 展示真实基础/未知内容与可用子代理样本 | 原始信息保留，基础内容可读，不执行不可信内容，不虚构协议详情 | PRD-LH-008 |
| AC-LH-010 | 在桌面和手机完成确认后的核心界面流程并安装、离线、更新 PWA | 与唯一完整设计一致，移动能力完整，更新保护上下文，离线不缓存敏感 API 或补发控制 | PRD-LH-002、007、011 |
| AC-LH-011 | 业务开发前演练两个固定候选，注入不健康、drain、Worker 交接与恢复 | 不健康不能切入，失效 generation 不能继续调度，兼容切回成功且证据绑定真实候选 | PRD-LH-012 |

## 12. 待确认的业务规则与建议

本节将已确定的需求与尚未确定的细节分开。建议仅用于帮助主人作决定；缺少答复不构成批准。受影响接口、业务模型和页面实现要等待对应规则收敛；同一个 UI 任务继续讨论与修订，不另开设计任务。

| 编号 | 尚需决定的规则 | 推荐起点，尚未批准 | 影响范围 |
| - | - | - | - |
| DEC-LH-001 | 同一对话能否成为多个任务的主对话，能否替换或解绑 | 一期一个对话至多关联一个任务；仅可关联尚无主对话的任务；替换、解绑和跨项目迁移暂不提供，明确提示冲突 | 对话/任务模型、绑定 API/MCP、任务工作区 |
| DEC-LH-002 | 无项目对话的权限及加入项目时历史可见性 | 无项目对话由创建者私有；加入项目需具备目标项目权限，并明确提示将按项目权限共享完整历史，关联与授权变更保持一致；其他成员不共享创建者的私人草稿 | 认证授权、Session/Run、事件/文件/草稿、工作台 |
| DEC-LH-003 | 共享草稿并发、发送时清理及离线恢复 | 同步以版本为依据；冲突保留双方内容并提示，不静默覆盖；发送只消费对应版本，较新输入保留；离线可保留未发送输入但恢复时对账，绝不自动发送。不承诺复杂 CRDT 编辑器 | 多端体验、草稿合同、发送/恢复、PWA |
| DEC-LH-004 | 任务状态、包含/依赖边界、编辑与删除规则 | 业务状态先采用待办/进行中/完成/取消；任务归属一个项目；包含与依赖限项目内，拒绝自环和环；用明确表单或动作维护关系；删除遇活跃执行或需保留历史则拒绝，改用取消。依赖本身不自动调度 | 任务 CRUD、关系模型、三视图、MCP |
| DEC-LH-005 | 小团队成员可以执行哪些操作，谁能答复审批和操作凭据 | 项目采用读取和操作两级能力，读取方不能执行或审批；操作方可执行及处理范围内审批；成员授权和安装/凭据管理由主人负责。独立对话仍按创建者私有，不引入组织/租户管理产品 | 身份授权、成员授权方式、审批、API/MCP |

DEC-LH-001、003、004 的用户交互由现有 UI 任务继续与主人收敛；DEC-LH-002、005 的产品取舍由主线程与主人确认。主线程负责最终汇总，不能要求主人在多个 Agent 间重复确认同一决定。技术实现可以另作方案，但不得用技术默认值替主人决定共享、丢失、授权或执行行为。
