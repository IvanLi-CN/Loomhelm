# 任务依赖图渲染与表达选型研究

研究依据为主人提供的截图与下列官方资料；未检查截图所属应用的渲染代码，未运行候选库基准测试。本文件是选型建议，不改变已确认设计或工程合同。

## 问题判断

截图中任务节点只有十余个，文字已经难以辨识。可见问题包括整图缩小、横向跨度大、汇聚连线难以追踪、节点类型采用不同形状但承载文字空间不足，以及大分组边框没有提供有效的信息压缩。是否由 fit-to-view、固定节点尺寸或具体布局器导致，仍需代码验证。

仅换 Canvas、SVG 或 WebGL 无法解决文字被缩小的问题。需要分别解决信息表达、节点与连线路由、视口与字号策略。

## 研究范围与推荐表达

主人明确要求只考虑免费可用的方案，优先开源。局部依赖展示留给后续浮动面板或详情面板，本次不研究邻域视图、局部图或详情侧栏，也不以这些功能补救全局图的可读性。

- 全局任务图采用固定阅读方向的分层布局，按依赖层级排列；横向与纵向方向应使用相同复杂数据对比，不预设横向一定更好。
- 保持任务卡片与文字的可读尺寸，允许平移浏览；“全图适配”作为主动操作，初始阅读不强求所有节点同时入屏。
- 多入边、多出边采用明确端口与正交路由，减少交叉和线穿节点；箭头与关系方向保持一致。
- 有自然业务分组时可以按交付单元或阶段组织全局图，聚合边保留真实关系清单与数量；不为美观虚构分组，也不以默认隐藏任务作为主要解决办法。
- 密集关系可评估独立的全局依赖矩阵作为辅助表达；它适合核对关系，不代替路径阅读，行列标题与排序需要单独设计。

上述为研究建议，尚未通过渲染实验。共享后继的多父 DAG 不能当作普通树处理；若后续采用分组折叠，仍需保持真实依赖语义。

## 免费开源技术候选

| 候选 | 能力与适配判断 | 主要代价 | 建议 |
| --- | --- | --- | --- |
| React Flow + elkjs | React 任务卡片与交互加 ELK 分层布局、端口及路由，适合当前 React 技术路线 | 需要开发 ELK 路由适配与布局稳定策略 | 首选验证 |
| Cytoscape.js + ELK 扩展 | 以网络图为核心，支持分组节点，官方提供 ELK 扩展入口 | 富 React 卡片与应用级可访问性需要额外集成；扩展许可需独立核对 | 全局关系图备选 |
| React Flow + Dagre | 简单方向图布局接入较轻 | 官方对比中没有边路由，且指出跨分组连接的已知限制 | 简单图基线，不作为复杂依赖的主要升级方向 |

上述适配与优先级是本研究判断。能力依据：[React Flow 布局对比](https://reactflow.dev/learn/layouting/layouting)、[ELK Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)、[Cytoscape.js 官方文档与扩展入口](https://js.cytoscape.org/)。

React Flow 核心采用 MIT；elkjs 采用 EPL-2.0；Cytoscape.js 核心与第一方扩展采用 MIT。选定版本与第三方扩展仍应核对其许可证及分发要求。来源：[React Flow](https://reactflow.dev/)、[elkjs 许可证](https://github.com/kieler/elkjs/blob/master/LICENSE.md)、[Cytoscape.js](https://js.cytoscape.org/)。推荐路径不依赖 React Flow Pro 示例或服务。商业 yFiles 与付费 Pro 示例已从候选及示例清单移除。

## 官方示例阅读顺序

1. [React Flow：ELK 多端口](https://reactflow.dev/examples/layout/elkjs-multiple-handles)：看多个前置与后继如何分配连接端口，减少交叉。它主要演示节点与端口布局，不应直接视为完整路由集成。
2. [React Flow：ELK 布局](https://reactflow.dev/examples/layout/elkjs)：看布局器与画布如何组合，并比较上下与左右方向；样例较小，不能证明业务复杂图的最终质量。
3. [ELK Layered 官方参考](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)：核对正交路由、端口、分组与跨层级边能力；这是算法参考，非完整产品演示。
4. [Cytoscape.js 官方 Demos](https://js.cytoscape.org/#demos)：从 ELK layout 和 Compound nodes 入口查看以关系图为核心的表达，作为备选比较。

## 推荐集成边界

React Flow 负责 HTML/React 节点、SVG 连线和视口交互，ELK 负责几何布局；这两层应与任务数据及分组投影分开。布局输入使用真实节点尺寸、稳定 ID、端口和关系；输出包含节点坐标及连线路径。React Flow 官方将其视为需要外接的布局能力，参见[布局说明](https://reactflow.dev/learn/layouting/layouting)。

若需要 ELK 的避让与折线路由，必须将输出 edge sections 的起点、折点和终点接入自定义 edge，并正确转换分组坐标。只应用节点坐标，再由 React Flow 默认边重新生成曲线，不等于使用了 ELK 的路由。ELK 支持正交路由与跨层级边，但需要相应配置，参见[算法参考](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)与[elkjs](https://github.com/kieler/elkjs)。

布局在结构变化时重新计算，状态颜色或进度更新尽量不触发布局。浏览器端优先考虑 Worker 计算与过期结果丢弃，保持用户缩放、选中项和阅读位置；不要在每次刷新后自动 fit 全图。这些是需要实现与验证的策略，不宣称 ELK 自动保证增量稳定。

## 可读性与验收建议

以下数值是验证起点，不是已经通过实验的结论。

- 桌面常规视口与浏览器 100% 缩放下，阅读模式任务标题以屏幕实际 14–16 px 为目标；节点宽度先试 220–280 px。字号按画布缩放后的实际结果判断。
- 图超出可读范围时允许平移；全图适配作为主动操作，不自动缩小到不可读。若另有聚合概览，应明确其信息层级。
- 在全局图中保持明确的依赖方向，通过文字和形态补充状态，避免仅依赖颜色；本轮不设计详情面板或局部关系展示。
- 用真实或脱敏的扇入、扇出、菱形共享后继、跨组依赖、长链、超长中文标题和循环异常验证。循环应明确标识，不擅自删除边来伪造 DAG。
- 对比 20、50、100 节点与不同边密度，记录默认文字可读性、追踪指定依赖的完成时间与错误、线穿节点、布局耗时和更新位移；这些规模是测试档位，不是性能承诺。

建议先用同一份复杂 fixture 验证 React Flow + ELK 的上下及左右分层布局，必要时与 Cytoscape.js + ELK 对比，再决定最终技术栈。首要验收目标是正常视口能读标题并追踪依赖，而不是整图可以完整塞进画布。

## 集成试验结论

任务编排面板现有 Cytoscape + Dagre 的首次替换试验仅应用节点坐标，未应用 ELK 连线路由；主人明确否决了该效果，该试验不能作为选型验收依据。当前候选改为 React Flow + elkjs：HTML 任务卡片统一承载类型、状态与标题，直接渲染 ELK edge sections 的正交路径，并按 edge container 转换分组坐标。

当前候选支持上下、左右两种布局，按主人要求默认横向。卡片宽度按标题在 136–184px 之间计算，高度按换行需求计算；缩短节点和层间距，标题保持 15px，100% 阅读与主动全图适配分开。相同结构的状态更新复用布局，异步旧结果丢弃；本次不新增局部依赖面板。集成行为与视觉效果仍待主人确认，不代表 PR 已发布或已完成正式审查。

真实运行数据只保留在本机临时重放页面中，不将编排账本、对话内容或认证信息提交到仓库。回放与原运行隔离，保留全部可见任务和投影关系，不修改原运行。
